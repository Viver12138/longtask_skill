# 文件模板

按当前操作选用对应模板；不要一次创建全部文件。模板中的占位符必须按事实填写，不适用项写「无」，未执行项写明原因。基础文件只有 `PROTOCOL.md`、`PLAN.md`、`STATE.md`；报告、锁、转换和备份按需生成。

## `.longtask/PROTOCOL.md`

从本包 `references/protocol.md` 完整复制，在头部附加实例信息，不重新起草协议：

```markdown
> 协议版本：1.7 · Schema 版本：1
> 任务 ID：<slug>-<short-id> · 任务短 ID：<short-id>
> 初始化：<带时区的时间> · 初始化 Agent：<实际身份>
```

旧任务保留其固定协议，不因安装新版本而覆盖。

```markdown
## 3. 现状与约束
<相关模块、已有成果和用户修改、关键未知、技术或业务约束>

## 4. 能力与降级
| 能力 | 实际状态 | 证据或降级方式 |

### 项目规则与授权来源

<实际相关的 OS、运行时、依赖锁文件、外部服务及前置条件>

|---|---|---|---|---|---|---|
| S01 | PLANNED | <产物> | <检查方法> | NONE | NOT_AVAILABLE | <文件范围与恢复方法> |

- <决策>：<理由、依据、影响范围>

无

- <影响交付的实际问题与下一步；没有则写无>
```

初始化所有单元均为 `PLANNED / NOT_AVAILABLE`，不可照抄示例中的完成状态。开始执行后按协议投影更新。

- PLAN 执行状态：`PLANNED`、`IN_PROGRESS`、`BLOCKED`、`HANDED_OFF`、`FAILED`、`CANCELLED`。
- 当前有效性：`NOT_AVAILABLE`、`VALID`、`REVALIDATION_REQUIRED`、`SUPERSEDED`。
- 依赖：`HARD` 开工前满足；`SOFT` 可提前开工但验收前满足；`NONE` 无前置依赖。
- 选择已规划会话时不要重新分配编号。新增单元才分配新编号；返工使用 `S02-R1`，并更新后续依赖。
- 每条验收检查写可复核的方法、预期结果和证据位置；命令检查还需副作用与幂等性。
- PLAN 只保留当前必要信息；历史细节引用交接记录，不复制完整日志。

## `.longtask/STATE.md`

```markdown
# 游标
- 任务：<slug>-<short-id> · 会话：S01 · 状态：PLANNED · 计划版本：v1
- 正在做：待开始
- 下一步：<能直接执行的具体动作或命令>
- 基线：<Git commit + 已有修改索引 / 文件基线>
- 所有者：未认领
- 最后更新：<带时区时间>
```

认领后所有者使用与锁一致的 `ownerId`，无可靠锁时注明单写入者降级的依据。按需追加「当前检查」「未完成操作」「阻塞原因」；通常 5–8 行，不为行数牺牲恢复信息。

会话状态取协议的八种值。默认在当前单元结束后切换；若按计划提前切换独立工作，先按协议 §3.4 保存原单元检查点。切换时通过 `TRANSITION` 同步计划与游标。非原子写入时保留 `.state.bak`，恢复损坏原文件后保留 `.state.corrupt-<timestamp>`。

## `.longtask/LOCK`

仅在平台支持可靠原子创建时使用；普通检查后写入不是互斥。

```json
{
  "taskId": "<slug>-<short-id>",
  "owner": {
    "agentType": "<agent-type>",
    "agentInstanceId": "<unique-run-id>",
    "sessionId": "<runtime-session-id>",
    "hostId": "<host-or-workspace-id>"
  },
  "ownerId": "<task-id>:<agentType>:<agentInstanceId>:<sessionId>@<hostId>",
  "createdAt": "<ISO-8601-time>",
  "renewedAt": "<ISO-8601-time>",
  "state": "HELD",
  "releaseReason": null
}
```

任务 ID 与 Owner 必须匹配。运行会话 ID 不是 `S01`；无法获得平台 ID 可生成唯一运行 ID 并持久化。创建、所有者续期、释放和接管都遵守协议 §9；失去所有权后不修改任何共享任务记录。锁为空或损坏也不能自动覆盖。

## `.longtask/TRANSITION`

仅在需要跨文件更新时写入；不是锁或业务操作重放队列。前后镜像路径相对于 `.longtask/`，应先实际保存文件与哈希，再写 `PREPARED`：

```json
{
  "transitionId": "<unique-id>",
  "taskId": "<task-id>",
  "sessionId": "S01",
  "ownerId": "<current-owner-id>",
  "fromState": "VERIFYING",
  "toState": "READY_FOR_HANDOFF",
  "phase": "PREPARED",
  "updatedFiles": ["STATE.md", "PLAN.md", "S01.md"],
  "snapshots": [
    {
      "path": "STATE.md",
      "before": "transitions/<id>/STATE.before.md",
      "after": "transitions/<id>/STATE.after.md",
      "beforeHash": "<sha256>",
      "afterHash": "<sha256>"
    }
  ],
  "evidence": ["<验收证据或确认来源的任务内路径>"],
  "timestamp": "<ISO-8601-time>"
}
```

`snapshots` 必须覆盖 `updatedFiles` 的每个文件，上面仅展示一项结构。新文件的 `before` 与 `beforeHash` 用 `null`。首次初始化没有旧游标时 `fromState` 用 `null`，并记录初始化目的。单元切换另记 `fromSessionId`、`toSessionId`，不能当作终态的逆向转换。

更新后按协议投影核对文件，再写 `COMMITTED`。恢复只能补齐有明确证据的元数据；未知变更或缺证据时报告，不重放业务动作，不恢复旧锁。

## `.longtask/S<nn>.md`

首次交接前生成草稿，通常约 60 行，必要证据可增加或引用附件。草稿可改；按逐次确认或有效预授权冻结后仅追加更正。历史记录性质以 PLAN 的历史单元状态为准，不看当前 STATE 的其他单元。

```markdown
# S01 交接

> 任务 ID：<task-id> · 计划版本：v1 · 生成时间：<带时区时间>
> 确认来源：<待确认 / 用户本次确认 / 既有持续执行授权的来源和范围>
> 冻结时间：<未冻结 / 带时区时间>

## 1. 结论
<产物、实际验收结果、证据位置；未执行的检查及原因>

## 2. 关键决策与理由
<无法从产物直接还原的理由，或无>

## 3. 被否决的方案及原因
<影响后续选择的方案，或无>

## 4. 踩过的坑
<症状、原因、规避方法，或无>

## 5. 遗留线索
<具体位置、未完成事项与下一步，或无>

## 6. 上一会话验收命令
<这里记录本单元的验收，供未来依赖本单元的会话使用；可为命令或审阅步骤>
- 检查与标准：<方法、目录、环境、预期>
- verification_mode：<EXECUTE / INSPECT / ASSERT>
- 幂等性 / 副作用 / 前置条件 / 授权来源：<按实际填写>
- 实际结果：<退出码及关键输出 / 审阅结论>
- 证据与适用版本：<路径或外部记录标识、产物版本、时间>
- 中断恢复：<如何检查是否已生效，或无>

## 7. 后续动作
- 下一会话第一条工作命令：<具体动作或命令；最后单元写无>
- 任务级最终验收结果：<尚未到 / 实际检查及证据>
- 最终任务完成情况：<完成 / 未完成及原因>
- 是否还有未完成事项：<无 / 具体清单>

## 8. Git 状态
- 开始/结束基线：<commit 或文件基线>
- 已有用户修改与本次变更边界：<文件/模块索引，含未跟踪产物>
- 恢复方式与风险：<补丁位置、同文件用户修改、必要限制，或无>
```

避免重复持久化，但不能删掉验收命令、退出码、证据和恢复信息。两条命令分别服务于「复核前置成果」与「开展后续工作」，不可混写；下一步始终以当前计划为准。

正式记录事实错误，在末尾追加：

```markdown
## 更正记录
- <日期>：<原文> → <更正内容>；依据：<证据>。
```

## `.longtask/reports/`

使用 Subagent 时按需创建，每个 Agent 只写自己的 `S01-<name>.md`。记录分配范围、输入、交付物、实际检查、未决问题；禁止改计划、游标、锁、转换或其他交接记录。主 Agent 核实实际变更；无法由子 Agent 保存时，由主 Agent 保存关键结论。

## 常驻指令与兜底启动语

采用 [通用适配](../adapters/generic.md) 的短加载片段。已有文件仅合并相关内容，不覆盖或重复追加；检查已有授权后再修改。没有自动加载能力时，直接向用户提供协议 §13 的恢复入口。

## 归档

按协议 §12 使用 `.longtask/archive/task-<slug>-<YYYYMMDD>-<short-id>/`。复制到临时归档目录，核对清单与内容后切换，再清理已验证源文件。保留交接、报告、转换证据和清单；不携带有效执行锁。失败保留源目录，不把整个 `.longtask/` 移进自己的子目录。
