# 文件模板

五段文本：前三段写进项目的 `.longtask/`，第四段写进 `AGENTS.md`，第五段给用户兜底。

## `PLAN.md`

创建于规划阶段，之后只追加「变更记录」。

```markdown
# 长任务计划：<任务名>

> 创建：YYYY-MM-DD · 状态：进行中 · 当前：S01

## 1. 任务目标
<一句话：完成后世界变成什么样>

## 2. 完成定义
<整体验收：可执行的检查清单>

## 3. 现状与约束
<存量项目：关键模块 / 技术栈 / 已知坑
 绿地项目：技术选型 + 理由、需求边界>

## 4. 会话划分
| 会话 | 目标 | 交付物 | 验收检查 | 依赖 | 可回滚性 |
|------|------|--------|----------|------|----------|
| S01  |      |        |          | —    |          |

## 5. 变更记录
- YYYY-MM-DD：<改了什么，为什么>

## 6. 风险与未决问题
```

字段约束：

- 「验收检查」一列必须能直接粘进终端执行，不接受「功能正常」这类描述。
- 「可回滚性」一列写本会话单独完成时能独立交付什么。写不出来说明会话之间有隐藏耦合。
- 「变更记录」只追加不修改，保留决策的历史。

## `STATE.md`

≤5 行，每个检查点覆盖重写。它是唯一敢高频写的文件，因为成本可忽略。

```markdown
# 游标
- 当前会话：S01
- 正在做：<交付物>
- 下一步：<可直接执行的具体动作>
- 最后更新：YYYY-MM-DD HH:MM
```

「下一步」必须是可执行动作。「继续实现认证」不合格，`npx jest src/auth/refresh.spec.ts -t "rotation failure"` 合格。

## `S0N.md`

≤60 行，收尾写一次，写完不再改。文件名与 `PLAN.md` 的会话编号一致（`S01.md`、`S02.md`）。

```markdown
# S01 交接

## 1. 结论
<做完 / 没做完，差什么>

## 2. 关键决策与理由
## 3. 被否决的方案及原因
## 4. 踩过的坑
## 5. 遗留线索
## 6. 下一会话的第一条命令
<可直接执行的具体动作，不是「继续实现」>
```

**只写无法从代码重建的东西。** 改了哪些文件（git 有）、测试输出（可重跑）、代码结构（可读）、任务背景（`PLAN.md` 有）——一律不写。超 60 行就删减。

## `AGENTS.md` 常驻指令

规划阶段结束时**作为提案**交给用户，确认后才写入项目根目录的 `AGENTS.md`。

```markdown
## 长任务模式

本项目存在 `.longtask/` 目录。任何会话开始时，若它存在：

1. 先读 `.longtask/STATE.md`（≤5 行）
2. 再读 `.longtask/PLAN.md` 的「会话划分」与「变更记录」
3. 再读当前会话的 `.longtask/S0N.md`（若存在）
4. 然后开始动手，不要重新探索代码库

纪律：
- 只做当前会话划分内的交付物，不提前做后续会话
- 每个检查点覆盖重写 `STATE.md`
- 收尾前逐条执行「收尾自检清单」，写 `S0N.md` 并等用户确认
- 代码与 `S0N.md` 不符时，以代码为准，并在 `S0N.md` 顶部标注「已过期」
```

若项目已有 `AGENTS.md`，**追加**到末尾，不要覆盖原有内容。

## 兜底启动语

给用户的一段话，用于新会话没加载 `AGENTS.md` 时手动粘贴：

> 本项目有进行中的长任务。先读 `.longtask/STATE.md` 和 `.longtask/PLAN.md`，再读当前会话的 `S0N.md`，然后开始。
