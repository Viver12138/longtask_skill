# 文件模板

模板覆盖以下文件：

- 项目 `.longtask/` 内：`PROTOCOL.md`、`PLAN.md`、`STATE.md`、`S<nn>.md`，按需使用 `reports/`
- 项目根目录的 `AGENTS.md`（或等价平台适配文件）
- 给用户的兜底启动语

`S<nn>.md` 是文档占位符。实际文件名使用具体编号：`S01.md`、`S02.md`、`S03.md`。

---

## `.longtask/PROTOCOL.md`

**从 `references/protocol.md` 完整复制**，只在头部补一段实例信息。不要在项目里重写协议正文。

```markdown
# longtask 执行协议（实例）

> 协议版本：1.1 · 来源：longtask skill `references/protocol.md`
> 任务 ID：<slug> · 初始化：YYYY-MM-DD · 初始化 Agent：<name>
> 本任务采用的执行协议以本文件为准；修改须经用户确认并记录到 PLAN.md 的「变更记录」。

---
<以下为 references/protocol.md 正文>
```

---

## `.longtask/PLAN.md`

创建于规划阶段。「当前有效决策」可修订，「变更记录」只追加。

```markdown
# 长任务计划：<任务名>

> 任务 ID：<slug> · 计划版本：v1 · 状态：ACTIVE · 创建：YYYY-MM-DD · 更新：YYYY-MM-DD

## 1. 任务目标
<一句话：完成后世界变成什么样>

## 2. 完成定义
- [ ] <整体验收检查，可执行>

## 3. 现状与约束
<存量项目：关键模块 / 技术栈 / 已知坑
 绿地项目：技术选型 + 理由、需求边界>

## 4. 能力与降级
| 能力 | 状态 | 降级方式 |
|---|---|---|
| 读取项目文件 | 可用 | — |
| 写入项目文件 | 可用 | — |
| Shell 执行 | 可用 | — |
| Git | 可用 | — |
| 自动加载项目指令 | 可用 | — |
| Subagent | 不可用 | 主 Agent 顺序执行 |
| 斜杠命令 | 可用 | — |

不可用的能力在「降级方式」列写明替代手段；可用的能力写「—」。

## 5. 验收环境
- 操作系统：
- 运行时版本：
- 包管理器及版本：
- 依赖锁文件：
- 数据库或外部服务版本：
- 必需环境变量（只记录变量名）：
- 测试前置条件：

## 6. 会话划分
| 会话 | 目标 | 交付物 | 验收检查 | 依赖 | 可回滚性 |
|---|---|---|---|---|---|
| S01 |  |  |  | — |  |
| S02 |  |  |  | S01 (HARD) |  |

依赖语义：`HARD` 必须等前置会话完成并通过验收；`SOFT` 可提前开展但最终依赖前置成果；`NONE` 无前置依赖。

## 7. 当前有效决策
- <决策>：<理由>

## 8. 已废弃决策
- <决策>：废弃原因 / 替代方案 / 变更日期

## 9. 变更记录
- YYYY-MM-DD：<改了什么，为什么，影响哪些会话>

## 10. 风险与未决问题
- <风险>：<影响 / 缓解措施>
```

字段约束：

- 「验收检查」必须能直接粘进终端执行，不接受「功能正常」这类描述。
- 「可回滚性」写本会话单独完成时能独立交付什么。写不出来，说明会话之间有隐藏耦合。
- 「当前有效决策」是新会话的唯一依据；被替代的决策必须移到「已废弃决策」，不能留在原处。
- 「变更记录」只追加不修改，保留决策历史。
- 任务状态取值：`PLANNING`、`ACTIVE`、`COMPLETED`、`ARCHIVED`。
- 没有相关信息的章节写「无」或省略可选项，不要为了字段齐全填无意义内容。

## `.longtask/STATE.md`

默认 5 行，每个检查点覆盖重写。它是唯一敢高频写的文件，因为成本可忽略。必要时可加 1–2 行备注，以能恢复任务为准。

```markdown
# 游标
- 会话：S02 · 状态：IN_PROGRESS · 计划版本：v1
- 正在做：<交付物>
- 下一步：<可直接执行的具体动作或命令>
- 基线：<git commit 或工作区标识> · 所有者：<agent/session> @ YYYY-MM-DD HH:MM
- 最后更新：YYYY-MM-DD HH:MM
```

可选第 6 行，仅在阻塞或异常恢复时需要：

```markdown
- 备注：<卡在哪里 / 为什么 / 恢复时需要先做什么>
```

约束：

- 状态取值必须是 protocol §3 定义的七种之一。
- 「下一步」必须是可执行动作。「继续实现认证」不合格，`npx jest src/auth/refresh.spec.ts -t "rotation failure"` 合格。
- 写入采用安全流程：生成完整内容 → 校验必填字段 → 临时文件 + 原子替换（平台支持时）→ 回读校验。平台不支持原子替换时，先备份再覆盖，不得声称已原子写入。
- 不是会话进度的权威来源：与代码冲突时以代码为准。

## `.longtask/S<nn>.md`（实际文件名如 `S01.md`）

≤60 行，收尾写一次，写完不再改。文件名与 `PLAN.md` 的会话编号一致。

```markdown
# S02 交接

> 计划版本：v1 · 交接状态：READY_FOR_HANDOFF · 完成时间：YYYY-MM-DD HH:MM

## 1. 结论
<做完 / 没做完，差什么；贴验收命令、退出码和关键数字；未执行的检查及原因>

## 2. 关键决策与理由
- <决策>：<为什么，为什么不是别的>

## 3. 被否决的方案及原因
- <方案>：<否决原因>

## 4. 踩过的坑
- <坑>：<症状 / 原因 / 规避方式>

## 5. 遗留线索
- <文件:行号 或 模块>：<问题 / 待办>

## 6. 下一会话的第一条命令
<可直接粘贴执行的一条命令>

## 7. Git 状态
- 开始基线：
- 结束基线：
- 未提交修改：
- 未跟踪交付物：
```

**只写无法从代码重建的东西。** 改了哪些文件（git 有）、测试输出（可重跑）、代码结构（可读）、任务背景（`PLAN.md` 有）——一律不写。超 60 行就删减。

交接状态取值：`READY_FOR_HANDOFF`、`HANDED_OFF`、`INCOMPLETE`、`OVERDUE`。

> 不需要复制完整 Git diff，只提供定位实际变更的索引。

## `.longtask/reports/`（按需）

只有使用 subagent 时才创建。每份报告一个文件：`S<nn>-<agent-name>.md`。

```markdown
# S02 · <subagent 名称> 报告

## 任务范围
<被分配的交付物与不做什么>

## 输入
<读取的文件、依赖、前置成果>

## 交付物
- <文件路径>：<说明>

## 验收结果
- `<命令>` → 退出码 <n>，<关键输出>

## 未决问题
- <问题 / 建议的下一步>
```

主 Agent 必须核实报告与实际交付物，不能只信报告。

## `AGENTS.md` 常驻指令（平台适配器）

规划阶段结束时**作为提案**交给用户，确认后才写入项目根目录的 `AGENTS.md`。

```markdown
## 长任务模式

本项目存在 `.longtask/` 目录。任何会话开始时，若它存在：

1. 读 `.longtask/PROTOCOL.md`（平台无关执行协议）
2. 读 `.longtask/PLAN.md` 的「当前有效决策」「会话划分」「变更记录」
3. 读 `.longtask/STATE.md` 确认当前会话与状态
4. 按会话编号读对应的 `.longtask/S<nn>.md`（若存在）
5. 检查项目文件与 Git 工作区，重跑上一会话的验收检查
6. 然后才开始动手，不要重新探索代码库

异常分支：
- `PROTOCOL.md` / `PLAN.md` / `STATE.md` 缺失或不可读 → 停止自动推进，向用户报告
- `STATE.md` 状态与代码冲突 → 以代码为准，标记异常
- 缺少交接文件 → 按 `PROTOCOL.md` §8 异常恢复，不得猜测进度
- 检测到其他主会话正在执行 → 停止并报告

纪律：
- 只做当前会话划分内的交付物，不提前做后续会话
- 每个检查点覆盖重写 `STATE.md`
- 收尾走两阶段交接：先置 `READY_FOR_HANDOFF` 并展示交接摘要，用户确认后才置 `HANDED_OFF`
- 代码与交接文件不符时，以代码为准，并在文件顶部标注「已过期」
```

若项目已有 `AGENTS.md`，**追加**到末尾，不要覆盖原有内容。写入前必须获得用户确认。

> 适配器只写「去读协议」和纪律摘要，不复制协议正文。协议升级后不需要同步修改每个项目。

---

## 兜底启动语

给用户的一段话，用于新会话没加载 `AGENTS.md` 或平台不支持自动加载时手动粘贴：

> 本项目有进行中的 longtask。先读 `.longtask/PROTOCOL.md`、`.longtask/PLAN.md` 和 `.longtask/STATE.md`，再按 `STATE.md` 的会话编号读对应的 `S<nn>.md`，然后按协议继续。重跑上一会话的验收检查之前不要改代码。

平台支持斜杠命令时，也可以直接输入 `/longtask` 并说明「继续当前会话」。
