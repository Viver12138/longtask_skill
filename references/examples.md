# 操作示例

按需阅读。示例用于说明决策，不是已执行的验证结果；完整规则见 [执行协议](protocol.md)。

## 1. 小任务与规划边界

用户：「把这段说明改得更清楚。」

正确：直接修改并检查，不创建 `.longtask/`，不以「不需要 longtask」为由停止原任务。

用户：「帮我规划一次跨模块重构，先不要动代码。」

正确：调查现状，生成可验收计划与恢复入口，保持 `PLANNING`。规划不授权实施。

用户：「按这个目标一直做完，过程中自行推进。」

正确：记录持续执行授权，在范围内依次完成单元、验收、草稿和交接。无需每个单元重复确认；发布等另有授权要求的动作单独核对。

## 2. 压缩后继续 S01

已保存：`S01 / IN_PROGRESS`，下一步是检查认证错误处理；实现文件存在，测试尚未完成。

正确：读取固定协议与游标、核实写权限和工作区，继续该测试。S01 没有前序交接是正常的，执行中断仍适用恢复流程。不要重建计划或新建 S02。

## 3. 多依赖和无依赖

| 单元 | 依赖 | 当前情况 |
|---|---|---|
| S01 | NONE | HANDED_OFF / VALID |
| S02 | NONE | PLANNED / NOT_AVAILABLE |
| S03 | S01 (HARD), S02 (HARD) | PLANNED / NOT_AVAILABLE |

S02 可执行，不需要因为编号是 02 就复核 S01；S03 必须等两个实际依赖均有效，不能只看相邻编号。若 S02 是 SOFT 依赖，可以提前做 S03，但其验收前仍须满足 S02。

S01 变成 `REVALIDATION_REQUIRED` 后，创建 S01-R1，调整 S03 依赖；不改写已冻结的 S01。

## 4. 人工审阅也是验收

交付物是调研报告时：

```text
检查：逐条核对需求清单与报告章节，验证每个关键结论的来源
模式：INSPECT
证据：报告版本、来源索引、未覆盖条目清单
结果：8 项要求均覆盖；2 个未确定假设已明确标注
退出码：不适用
```

不把「报告不错」当验收，也不为凑命令虚构终端输出。

## 5. 确认与最终验收

```text
IN_PROGRESS → VERIFYING
→ 会话检查通过，形成草稿
→ 若已无其他必要单元，完成任务级最终检查
→ READY_FOR_HANDOFF，展示结果
→ 用户确认或适用的持续执行预授权
→ 冻结并记录依据，HANDED_OFF
→ 最终交接完成且整体检查通过，任务 COMPLETED
```

用户要求修改时，`READY_FOR_HANDOFF → IN_PROGRESS`，修改后重新验收。最终检查失败不能仅靠本单元测试成功就完成任务。

## 6. 正常投影与真正的半更新

`STATE=READY_FOR_HANDOFF`、`PLAN=IN_PROGRESS` 正常，因为计划保存较粗的投影。

`STATE=HANDED_OFF`、`PLAN=IN_PROGRESS`，且 `TRANSITION=PREPARED`：

1. 核实所有权，读取该转换的前后镜像与证据。
2. 检查实际交付物、验收和确认来源。
3. 确认只有预期元数据尚未写完时，补齐计划再提交转换。
4. 若文件包含第三方修改或缺少证据，保留现场并报告。

不能在恢复中重跑发布或迁移；不能只看两个状态字符串不同就宣布损坏。

## 7. 丢锁和等待回复

A 持有锁，B 认领失败：B 只报告冲突，不写共享 PLAN 将自己标为 BLOCKED。

A 正常等待用户确认：先保存草稿和游标，再释放自身锁；确认到达后重新认领并核对文件。

A 异常退出：保留锁。接管前确认 A 已停止；仅时间较久不构成证明。A 后来恢复发现 Owner 为 B 时停止，不删除 B 的锁，也不继续改项目。

## 8. 非幂等操作中断

数据库迁移调用超时，无法确定是否生效：

- 查迁移记录和当前 schema，用 `INSPECT` / `ASSERT` 确认结果。
- 已生效：记录观察与证据，不重复执行。
- 未生效：核对前置条件、失败影响和已有授权后决定修复/重试。
- 不能确定：报告所缺信息，不因为「之前已授权」盲目重试。

## 9. 证据与用户修改

交接记录保存验收方法、结果、版本和日志路径；大日志不用复制，但不能以「可重跑」为由删掉全部证据。

同文件有用户与 Agent 修改时先核对 diff，必要时保存补丁；只能恢复明确属于自己的部分。不能整文件还原，归属不明就保留并报告。

## 10. 归档与旧任务

完成任务有归档授权后，暂停其他写入者，按清单复制到临时归档目录、核对内容、切换正式目标，再清理已验证源文件。中断保留源文件，不把目录存在当成功，不把 `.longtask/` 整体移入自己的 archive 子目录。

新安装 skill 不覆盖旧任务协议；旧任务缺少确认策略不能自动解释为预授权。完成或归档的任务不因加载片段再次出现而重新执行。
