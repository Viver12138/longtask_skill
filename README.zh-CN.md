# longtask

[English](README.md) | **简体中文**

> 把一个长任务拆成多个可独立验收的会话，并留下能扛过上下文压缩的交接痕迹。

一个 [Agent Skill](https://agentskills.io)——纯 `SKILL.md` 加两个参考文件。无依赖、无脚本。

---

## 要解决的问题

长任务的 agent 会从两个方向失败：

1. **压缩吃掉推理过程。** 你花一小时想清楚某个方案为什么被否决，摘要只留下结论，不留推理。下一个会话会把被否掉的方案重新提一遍。
2. **会话之间接不上。** 新会话不知道上一个会话做完了什么，只能重新探索代码库——把上下文烧在上一个会话已经干过的事情上。

`longtask` 两头都治：开工前把任务拆成每个都能交付**可独立验收**产物的会话；然后在项目里建一个 `.longtask/` 目录，让之后每个会话在动手前先读它。

## 工作原理

### 阶段一——规划（`/longtask`）

- **先判定要不要做。** 三种情况直接退出：单会话装得下、没有可验收的交付物、需求还在剧烈变动。
- **带预算地探索。** 存量项目读 5–10 个关键文件加跑一次构建或测试；绿地项目探索需求边界、技术选型和目录骨架。结论必须落盘，不能只留在上下文里。
- **按交付物切，不按 token 数切。** 每个会话必须产出能被一条命令验证的东西。写不出这条检查，说明切分是错的，退回去重切。
- **搭骨架。** 建 `.longtask/`，写入计划、五行游标和一份空的会话交接。

### 阶段二——协议（写进 `AGENTS.md` 的一段）

- 动手前先读游标、计划和当前会话的交接文件。
- 每个检查点覆盖重写游标。
- 写交接前过六道闸门。任一条不过，就改为记录**卡在哪里**——一份撒谎的交接比没有交接更糟。
- 新会话开工前，**重跑上一会话的验收命令**再继续。

## 安装

把 `longtask/` 目录复制进你的 skills 目录：

```bash
# 全局——所有项目可用
cp -r longtask ~/.kscc/skills/

# 或只对当前项目生效
mkdir -p .kscc/skills && cp -r longtask .kscc/skills/
```

## 使用

```bash
/longtask
```

然后描述任务。skill 要么给你一份计划，要么告诉你这不需要规划。

计划一旦建立，之后每个会话都会通过 `AGENTS.md` 自动接上。若某个会话没加载那个文件，粘一句兜底启动语：

> 本项目有进行中的长任务。先读 `.longtask/STATE.md` 和 `.longtask/PLAN.md`，再读当前会话的 `S0N.md`，然后开始。

## `.longtask/` 里的文件

| 文件 | 写入时机 | 篇幅 | 用途 |
|---|---|---|---|
| `PLAN.md` | 建一次，之后只追加 | — | 目标、完成定义、现状与约束、会话划分表、变更记录 |
| `STATE.md` | 每个检查点 | ≤ 5 行 | 游标：当前会话、正在做、下一步具体动作 |
| `S0N.md` | 会话收尾写一次 | ≤ 60 行 | 交接：结论、关键决策、被否方案、踩过的坑、遗留线索、第一条命令 |

三个文件都进 git。它们是决策记录，不是临时草稿。

## 设计原则

- **只写代码无法重建的东西。** git 有 diff，测试可以重跑，代码本身可读。缺的是*为什么*——交接文件就是为这个存在的。
- **高频轻量，低频完整。** 游标便宜到可以反复重写；交接昂贵，所以只写一次。两者合起来，既兜住崩溃，也兜住正常的切会话。
- **不预测压缩。** agent 无法预知何时被压缩，所以「压缩前存盘」做不到，只能在检查点写。
- **subagent 必须落盘。** subagent 的报告只回到父会话。不写进 `.longtask/`，就等于没做。

## 反模式

- **把所有任务都套进流程**——能说「不需要我」的 skill 才值得信任。
- **凭描述切分**——没读过代码切出来的计划，第二个会话就会推翻。
- **把变更日志写进 `S0N.md`**——它会自己长大，长成它本来要解决的那个压缩问题。
- **在 `S0N.md` 里写「继续实现 X」**——下一个会话照样不知道该敲什么。
