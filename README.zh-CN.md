# longtask

[English](README.md) | **简体中文**

把跨上下文任务拆成可验收的工作单元，用 `.longtask/` 保留决策、进度和恢复证据。

这是一个平台无关的 Agent Skill。核心是 Markdown 指令与文件模板；执行任务不依赖额外运行库。源码维护检查使用 Node.js 20 或更高版本，无第三方依赖。

## 使用

- 「用 longtask 规划这次跨模块重构，先不要实施。」
- 「按这个目标持续推进到完成，保留检查点方便恢复。」
- 「继续项目里的 longtask，从当前进度恢复。」

平台支持时可以用 `/longtask`；自然语言入口不依赖斜杠命令。小任务直接完成原请求，不强制创建任务目录。研究和写作只要有可复核的交付物也适用。

**工作单元不等于聊天窗口。** 同一聊天可以连续完成多个单元；压缩后可以继续原单元。仅要求规划不会自动实施。持续执行已获授权时，不在每次交接重复请求确认。

## 工作方式

1. 调查现状与约束，明确目标、范围和整体完成条件。
2. 按交付物切分，记录检查方法、实际依赖和变更边界。
3. 创建协议固定副本、计划与当前游标。
4. 保存检查点；交接前验收并形成完整草稿，再依据用户确认或有效预授权冻结。
5. 恢复时先核实所有权、产物和未完成操作，复核所需依赖，再继续工作。
6. 当前范围全部必要成果通过任务级最终验收，且最终交接完成，才标记完成。

| 文件 | 用途 |
|---|---|
| `PROTOCOL.md` | 本任务固定的执行规则与版本 |
| `PLAN.md` | 目标、依赖、历史状态、有效性、决策和授权依据 |
| `STATE.md` | 当前单元、进度、下一步、所有者与基线 |
| `S01.md` 等 | 交接证据与理由；冻结后只追加更正 |
| `LOCK` | 按平台能力使用的所有权记录 |
| `TRANSITION`、`transitions/` | 跨文件更新意图和前后证据；不重放业务操作 |
| `.state.bak` | 非原子写入时的最后有效备份 |
| `reports/` | 按需保存子 Agent 结果 |

只初始化前三个文件，其他按需生成。没有写文件能力时明确尚未持久化，没有执行能力时不把检查写成通过。

## 安装

仓库根目录就是 skill 包。将 `SKILL.md`、`references/`、`adapters/` 放入目标平台实际配置的 skills 目录，文件夹命名为 `longtask`。初次安装和已有版本升级分开处理，避免覆盖用户修改。

具体 POSIX Shell / PowerShell 示例、最小安装结构和短加载片段见 [通用适配](adapters/generic.md)。该页面不假定特定平台的目录或自动加载行为。

新聊天手动恢复：

> 请继续本项目的 longtask。先读 `.longtask/PROTOCOL.md`、`.longtask/PLAN.md`、`.longtask/STATE.md`，按固定协议检查所有权、未完成转换和实际产物，恢复当前单元或选择满足依赖的下一单元。不要盲目重跑有副作用操作。

## 关键边界

- 计划中的规则登记是索引，不能取消平台或用户已指定的规则，也不能授予新权限。
- 验收可执行命令，也可复核报告、设计和其他产物；必须有明确标准与证据。
- 非幂等操作先查结果，已有授权不意味着应该重复执行。
- 没有写权限的会话不修改共享状态；文件锁不保证强制接管时的完整隔离。
- 保留用户修改、关键证据和冻结历史；不因行数限制删除恢复信息。
- 旧任务保留固定协议。升级安装不会静默迁移任务或推断其具有预授权。
- 完成后保留记录。归档按授权写入 `.longtask/archive/task-<slug>-<YYYYMMDD>-<short-id>/`，不覆盖旧归档。

## 验证与成熟度

在源码仓库运行：

```sh
node scripts/validate.mjs
node --test scripts/validate.test.mjs
```

静态检查覆盖入口元信息、编码、链接、状态集合、完整转换白名单、状态投影、关键模板字段和权限表。回归测试验证检查器能拒绝非法输入；它不是 longtask 执行引擎，也不证明 Agent 会遵守所有自然语言规则。

[验证矩阵](references/validation.md) 保留协议模拟与真实 Agent 场景。**协议模拟和跨平台真实 Agent 集成尚未执行；当前为受控试运行。** 新增的检查器测试不冒充协议模拟、并发压力测试或跨聊天恢复验证。CI 运行上述两条命令。
